1. Key Concepts

mvn install compiles, packages, and copies the artifact (JAR + POM) into your local Maven repository at ~/.m2/repository/. Once there, any project on your machine can depend on that artifact by its GAV (groupId:artifactId:version) coordinates.

Maven Coordinates (GAV)

<!-- How Maven identifies every artifact -->
<groupId>org.apache.hadoop</groupId>
<artifactId>hadoop-azure</artifactId>
<version>3.4.3</version>

<!-- Maps to file path: -->
~/.m2/repository/org/apache/hadoop/hadoop-azure/3.4.3/hadoop-azure-3.4.3.jar
             ^groupId (dots→dirs)  ^artifactId   ^ver  ^artifactId-version.jar

POM-only vs JAR modules

Aggregator/parent POMs (packaging=pom) define shared config, dependency versions, and module lists. They produce no JAR — just a POM file in the repo. Use mvn install -N (non-recursive) to install only the POM itself.

JAR modules contain actual compiled code. Use mvn install to compile, package, and install the JAR.

5. Phase 1: Install Parent/Aggregator POMs

These have <packaging>pom</packaging> and define shared config. Use -N (non-recursive) to install just the POM.

# All commands run from hadoop fork root: ~/Workspaces/hadoop
# Step 1: Root POM
mvn install -N -pl .

# Steps 2-3: Project POMs
cd hadoop-project  && mvn install -N && cd ..
cd hadoop-project-dist && mvn install -N && cd ..

# Steps 4-9: Aggregator POMs (can run in parallel)
cd hadoop-common-project && mvn install -N && cd ..
cd hadoop-hdfs-project   && mvn install -N && cd ..
cd hadoop-tools           && mvn install -N && cd ..
cd hadoop-yarn-project    && mvn install -N && cd ..
cd hadoop-yarn-project/hadoop-yarn && mvn install -N && cd ../..
cd hadoop-client-modules && mvn install -N && cd ..
Known Issue: hadoop-yarn-project/pom.xml has a missing <version> for hadoop-yarn-applications-catalog-webapp:war. Fix by adding <version>${project.version}</version> to that dependency.

6. Phase 2: Build & Install Module JARs

CRITICAL: Hadoop 3.4.3 has a jdk17+ Maven profile that auto-activates on JDK ≥17 and sets javac.version=17. Since Dremio targets JDK 11, you must override: 
-Djavac.version=11 -Dmaven.compiler.release=11
Without this, you'll get UnsupportedClassVersionError: class file version 61.0 at runtime. 
# Common flags for all module builds
FLAGS="-DskipTests -Dmaven.javadoc.skip=true -Dpmd.skip=true -Dcheckstyle.skip=true \
       -Dfindbugs.skip=true -Dspotbugs.skip=true \
       -Djavac.version=11 -Dmaven.compiler.release=11"

# Step 10: hadoop-common (must be first - everything depends on it)
cd hadoop-common-project/hadoop-common && mvn clean install $FLAGS && cd ../..

# Steps 11-13: Can run in parallel (all depend only on hadoop-common)
cd hadoop-common-project/hadoop-auth     && mvn clean install $FLAGS && cd ../..
cd hadoop-common-project/hadoop-nfs      && mvn clean install $FLAGS && cd ../..
cd hadoop-common-project/hadoop-registry && mvn clean install $FLAGS && cd ../..

# Step 14: hadoop-hdfs-client (depends on hadoop-common)
cd hadoop-hdfs-project/hadoop-hdfs-client && mvn clean install $FLAGS && cd ../..

# Step 15: hadoop-hdfs (depends on common, auth, nfs, hdfs-client)
cd hadoop-hdfs-project/hadoop-hdfs && mvn clean install $FLAGS && cd ../..

# Steps 16-18: Tools (can run in parallel, depend only on common)
cd hadoop-tools/hadoop-aws             && mvn clean install $FLAGS && cd ../..
cd hadoop-tools/hadoop-azure           && mvn clean install $FLAGS && cd ../..
cd hadoop-tools/hadoop-azure-datalake  && mvn clean install $FLAGS && cd ../..

# Steps 19-21: YARN (sequential chain)
cd hadoop-yarn-project/hadoop-yarn/hadoop-yarn-api    && mvn clean install $FLAGS && cd ../../..
cd hadoop-yarn-project/hadoop-yarn/hadoop-yarn-common && mvn clean install $FLAGS && cd ../../..
cd hadoop-yarn-project/hadoop-yarn/hadoop-yarn-client && mvn clean install $FLAGS && cd ../../..

# Steps 22-23: Client (shaded jar - takes ~1min)
cd hadoop-client-modules/hadoop-client-api && mvn clean install $FLAGS && cd ../..
cd hadoop-client-modules/hadoop-client     && mvn clean install $FLAGS && cd ../..

7. Phase 3: Placeholder Artifacts

hadoop-common-native is a platform-specific native library built in CI. For local testing on macOS, create empty placeholder JARs.

# Create placeholder jar
mkdir -p /tmp/placeholder && echo "placeholder" > /tmp/placeholder/p.txt
jar cf /tmp/placeholder/empty.jar -C /tmp/placeholder p.txt

# Install with classifiers
mvn install:install-file \
  -DgroupId=org.apache.hadoop \
  -DartifactId=hadoop-common-native \
  -Dversion=3.4.3 \
  -Dclassifier=linux \
  -Dpackaging=jar \
  -Dfile=/tmp/placeholder/empty.jar

mvn install:install-file \
  -DgroupId=org.apache.hadoop \
  -DartifactId=hadoop-common-native \
  -Dversion=3.4.3 \
  -Dclassifier=linux-aarch64 \
  -Dpackaging=jar \
  -Dfile=/tmp/placeholder/empty.jar
How positioning is determined: mvn install:install-file uses the GAV + classifier to compute the path: 
~/.m2/repository/{groupId with . → /}/{artifactId}/{version}/{artifactId}-{version}-{classifier}.jar

Example:
~/.m2/repository/org/apache/hadoop/hadoop-common-native/3.4.3/hadoop-common-native-3.4.3-linux.jar

8. Phase 4: Update Dremio Version Properties

Edit oss/pom.xml and update two properties:

<!-- Line ~82: Main hadoop version -->
<hadoop.version>3.3.6-dremio-...</hadoop.version>
                 ↓ change to ↓
<hadoop.version>3.4.3</hadoop.version>

<!-- Line ~110: Hive3 plugin hadoop version -->
<plugin.hive3.hadoop.version>3.3.6-dremio-...</plugin.hive3.hadoop.version>
                               ↓ change to ↓
<plugin.hive3.hadoop.version>3.4.3</plugin.hive3.hadoop.version>
Version property chain: These two properties drive everything else: 
hadoop.version = 3.4.3
  → used by hadoop-common, hadoop-hdfs, hadoop-client, hadoop-yarn-api, hadoop-yarn-client

plugin.hive3.hadoop.version = 3.4.3
  → plugin.hive3.hadoop-azure.version = ${plugin.hive3.hadoop.version}
  → plugin.hive3.hadoop-azure-datalake.version = ${plugin.hive3.hadoop.version}
  → plugin.hive3.aws-hadoop.version = ${plugin.hive3.hadoop.version}
  → hadoop-azure.version = ${plugin.hive3.hadoop-azure.version}

9. Phase 5: Compile & Test Dremio

# From dremio root

# Compile key modules
./mvnw clean compile -pl oss/plugins/azure -DskipTests
./mvnw clean compile -pl oss/sabot/kernel -DskipTests
./mvnw clean compile -pl oss/plugins/hive3/plugin -DskipTests

# Run tests
./mvnw clean test -pl oss/plugins/azure
./mvnw clean test -pl oss/plugins/azure -Dtest=TestAzureSharedKeyCredentials

10. Maven Local Repository Structure

~/.m2/repository/org/apache/hadoop/
  hadoop-azure/
    3.4.3/
      hadoop-azure-3.4.3.jar          ← compiled module JAR
      hadoop-azure-3.4.3-tests.jar    ← test JAR (for test deps)
      hadoop-azure-3.4.3.pom          ← module POM (dependencies)
      _remote.repositories             ← Maven metadata
  hadoop-common/
    3.4.3/
      hadoop-common-3.4.3.jar
      hadoop-common-3.4.3-tests.jar
      hadoop-common-3.4.3.pom
      *.sha1, *.lastUpdated            ← checksum/cache metadata
  hadoop-common-native/
    3.4.3/
      hadoop-common-native-3.4.3-linux.jar         ← classifier in filename
      hadoop-common-native-3.4.3-linux-aarch64.jar
      hadoop-common-native-3.4.3.pom
  hadoop-project/
    3.4.3/
      hadoop-project-3.4.3.pom        ← POM-only, no JAR
Path formula: 
~/.m2/repository/{groupId.replace('.','/')}/{artifactId}/{version}/{artifactId}-{version}[-{classifier}].{packaging}
  • groupId org.apache.hadoop → org/apache/hadoop/
  • classifier (optional) appears between version and extension: -linux, -tests
  • packaging is usually jar or pom

11. Gotchas & Pitfalls

PitfallSymptomFix
JDK 17 auto-profile UnsupportedClassVersionError: class file version 61.0 Add -Djavac.version=11 -Dmaven.compiler.release=11 to all builds
Missing parent POM Non-resolvable parent POM Install parent POMs first with mvn install -N
Stale cache in .m2 was not found in ... during a previous attempt Delete the .lastUpdated files or add -U flag
hadoop-common-native missing DependencyResolutionException for native classifiers Create placeholder JARs with mvn install:install-file
hadoop-yarn-project POM broken version for catalog-webapp:war is missing Add <version>${project.version}</version> to the dependency
"Nothing to compile" Maven skips compilation after version change Use mvn clean compile to force recompilation
Don't use -am flag Builds unrelated modules, hits broken POMs Build each module individually in dependency order

12. Quick Reference: Updating a Single Module

If you only changed one module (e.g., hadoop-azure), you don't need to rebuild everything:

Minimal Steps to Update hadoop-azure

# 1. Rebuild just the changed module
cd ~/Workspaces/hadoop/hadoop-tools/hadoop-azure
mvn clean install -DskipTests -Djavac.version=11 -Dmaven.compiler.release=11

# 2. Recompile affected Dremio module
cd ~/Workspaces/dremio
./mvnw clean compile -pl oss/plugins/azure -DskipTests

# 3. Run tests
./mvnw test -pl oss/plugins/azure

If your change affects hadoop-common (a foundational module), you must rebuild all downstream modules that depend on it.
